# 1、http协议问题（http 1.0 1.1 2.0的区别）

（1）http 1.0：

a、一次请求一次连接，用完即关（TCP 三次握手开销大）
b、无缓存控制

（2）、http 1.1

a、长连接：一个 TCP 连接可以发送多个请求
b、管道化：响应必须按请求顺序返回

（3）、http 2.0

a、二进制分帧：传输的不再是文本，而是流
b、多路复用：多个请求并行，响应可以乱序返回
c、头部压缩：只传变化的 header，大幅减少 header 体积
d、服务器推送：服务器主动推送 css / js
e、优先级控制：JS > CSS > 图片

# 2、强缓存和协商缓存（请求头中是通过什么字段分别控制强缓存和协商缓存）

(1)、强缓存是指浏览器在访问资源时，先检查本地缓存是否命中。如果命中且资源未过期，则直接使用缓存，不会向服务器发送任何请求。

（2）、当强缓存失效（过期）或者开发者设置了 no-cache 时，浏览器会携带缓存标识向服务器发起请求，由服务器决定资源是否可以继续使用。

### 强缓存：

a、Expires(HTTP/1.0)（服务器返回的一个绝对时间，浏览器将当前本地时间与该时间对比，依赖客户端本地时间，如果客户端时间不准确，缓存控制会失效）
b、Cache-Control (HTTP/1.1)（相对时间）
public：资源可以被客户端和代理服务器（如 CDN）缓存。
private：资源只能被客户端缓存。
no-cache：跳过强缓存，直接进入协商缓存阶段。
no-store：完全禁用缓存，每次都重新下载。

### 协商缓存:

控制字段（两对组合）：
第一对：根据修改时间 (Last-Modified / If-Modified-Since)
Last-Modified (响应头)： 服务器告知浏览器资源最后一次修改的时间。
If-Modified-Since (请求头)： 再次请求时，浏览器带上之前存的修改时间。服务器比对，如果资源没变，返回 304 Not Modified。
第二对：根据资源指纹 (ETag / If-None-Match) - 优先级更高
ETag (响应头)： 服务器为每个资源生成的唯一哈希字符串（只要内容变，字符串就变）。
If-None-Match (请求头)： 再次请求时，浏览器带上这个字符串。服务器比对，一致则返回 304。
优点： 解决时间精度问题（Last-Modified 只能精确到秒）以及文件内容没变但修改时间变了的问题。

# 3、浏览器的渲染原理

（1）、构建 DOM 树和构建 CSSOM 树（CSS 解析是阻塞渲染的）
（2）、将 DOM 和 CSSOM 合并，生成一棵“渲染树”Render Tree。（display: none; 的元素不会出现在渲染树中，但 visibility: hidden; 的元素会，因为它占据空间）
（3）、重排（浏览器需要计算每个节点的精确位置和几何尺寸，触发条件： 修改元素位置、尺寸、添加/删除 DOM、浏览器窗口缩放等）
（4）、重绘：计算出的每个矩形框转换成屏幕上的实际像素（这包括绘制文本、颜色、图像、边框、阴影等，绘制通常是在多个层 Layers 上进行的，触发条件： 修改背景色、文字颜色、visibility 等不影响几何位置的属性。）
（5）、合成：将之前生成的各个图层Layers按照正确的顺序组合在一起，显示在屏幕上。（合成线程： 现代浏览器通常在专门的“合成线程”中处理这一步，不占用主线程。优化技巧： 使用 transform 或 opacity 做动画可以避开重排和重绘，直接在合成阶段处理，性能最高）

### 注意点1：

浏览器会根据以下条件决定是否为一个节点创建合成层（Compositing Layer）：
a、硬件加速属性： 使用了 transform (3D 变换)、opacity、filter、will-change 的元素。
b、特殊的 HTML 标签： <video>、<canvas>、<iframe> 标签。
c、层叠上下文（Z-Index）层压： 如果一个元素 A 覆盖在另一个已经拥有独立图层的元素 B 之上，为了保证显示顺序正确，元素 A 也会被提升为一个独立图层（这被称为“层爆炸”风险）。
d、层叠上下文是 CSS 渲染引擎的一个逻辑概念，决定了元素“谁遮挡谁”，合成层layers是浏览器引擎的一个物理实现，决定了元素“如何被绘制和渲染”。

### 注意点2：

使用 DocumentFragment： 你先在内存中创建一个“袋子”（Fragment），把 100 个 <li> 塞进这个袋子里。此时，袋子还没挂载到真正的页面上，所以浏览器不会触发任何渲染计算。最后，你只需一次性把整个袋子里的内容倒进 <ul>，浏览器只执行 1 次 重排。
DocumentFragment 有一个非常神奇的特性：它本身不会被插入到 DOM 中。
当你执行 document.getElementById('list').appendChild(fragment) 时：
被插入到页面上的是 fragment 的所有子节点。

### 注意点3：在浏览器的工作循环中，JS 引擎和渲染引擎是互斥的

# 4、宏任务和微任务的函数有哪些

### 宏任务

setTimeout、setInterval、setImmediate、I/O 操作、UI 渲染 (UI Rendering)（浏览器自身的重绘和重排动作。）
script (整体代码)（第一次加载的同步代码块本质上是第一个宏任务。）、MessageChannel（用于窗口间通信，常被用来模拟宏任务优化性能。）

### 微任务

Promise.then / catch / finally：new Promise 构造函数是同步的，但其 then 等回调是微任务。
process.nextTick：优先级最高的微任务，在当前调用栈清空后立即执行。
MutationObserver：监听 DOM 树变化的回调。
queueMicrotask：现代原生 API，专门用于手动向微任务队列添加任务。
Async / Await：await 后面的代码会被包装成微任务（本质是 Promise 的语法糖）。
